# ETF 輪動（規則化雙動量）

`python main.py --etf-rotation` 基於一組事先定好的 ETF，輸出**最新調倉信號**和**規則回測報告**。整個流程是純規則計算，不調用 LLM，不依賴任何 AI 配置。

## 規則

1. **調倉日**：每週（或每月）最後一個交易日收盤後計算信號，下一個交易日收盤執行，避免使用信號當天的價格成交（防未來函數）。
2. **相對動量**：按過去 `ETF_ROTATION_LOOKBACK_DAYS` 個交易日的漲幅，對風險池中的 ETF 排名。
3. **絕對動量**：只有漲幅為正的 ETF 才能入選。每個名額佔 `1/ETF_ROTATION_TOP_N` 倉位，沒選滿的名額轉到防守資產 `ETF_ROTATION_SAFE_ASSET`；防守資產未配置或不可用時，按現金（收益為 0）處理。
4. **換倉緩衝**：已持有的 ETF 只要仍然合格，且動量落後最後一個入選名額不超過 `ETF_ROTATION_SWITCH_BUFFER_PCT` 個百分點，就繼續持有，用來減少來回切換。
5. **只在組合變化時交易**：入選組合不變時不做任何交易，漂移後的權重也不會被重新拉回等權。
6. **交易成本**：每次調倉按 `換手率 × ETF_ROTATION_COST_BPS` 扣除。換入、換出現金不計換手。

計算僅接受明確採用前復權的 A 股 ETF 數據路徑：Efinance、AkShare、Baostock，以及配置為 `forward` 的 TickFlow，保持這些來源原有的優先級和失敗切換。Tushare、Pytdx、未前復權的 TickFlow 不作為本命令的兜底；沒有合格來源時明確告警並剔除標的，不把未復權價格當成可用數據。調用方注入行情服務時，返回的 DataFrame 必須聲明 `attrs["price_adjustment"]="forward"`。這些限制只作用於 ETF 輪動，不修改普通股票分析的數據源鏈。

風險池中尚未上市或歷史不足的 ETF，在積累夠 `LOOKBACK` 天數據之前不參與排名。短缺口僅為動量計算前填最多 5 根，當前沒有真實有效收盤價的 ETF 不參與當日排名；參數掃描與主回測使用同一原始行情，不重複填補。

缺報價日不能買入或賣出，需交易的標的沒有當日有效報價時跳過該次調倉，保留原持倉，等待後續計劃調倉日。持倉在缺口期間按最後有效報價估值；恢復報價時計入相對於最後報價的完整漲跌，不把虧損吞掉。防守 ETF 在執行日沒有報價時，空缺倉位保持現金；已有防守持倉缺報價時也不能虛構賣出。防守 ETF 最新沒有報價，報告目標顯示現金，並告警其不可用。該目標不保證下一個交易日可成交。

數據截止到最近一個**已收盤**的 A 股交易日：盤中運行時，當天未收盤的 K 線會被丟棄。

行情按真實 A 股交易日曆對齊到該截止日，保留所有標的同時缺報價的交易日（包括末尾缺口），不把週末或節假日當作交易日。週一缺報價不會把上週的買入順延到週二；週五缺報價也不會提前到週四產生週末信號。歷史交易日曆不可用或超出支持範圍時明確報錯，停止生成輪動報告，避免用報價日期代替交易日曆。

## 使用

```bash
python main.py --etf-rotation              # 生成報告並按已配置渠道推送
python main.py --etf-rotation --no-notify  # 只生成本地報告
```

報告保存在 `reports/etf_rotation_YYYYMMDD.md`（日期取數據截止交易日，包括末尾缺報價日），包含以下內容：

| 章節 | 內容 |
| --- | --- |
| 數據告警 | 取數失敗、歷史被截斷、單日異常漲跌（疑似拆分或復權缺失）、多個數據源混用 |
| 最新信號 | 當前規則持倉、按最新收盤計算的目標持倉、是否需要調倉，以及動量排名。最新收盤不是本週（本月）最後一個交易日時，目標持倉只作參考；交易日曆不可用時會註明無法確認 |
| 回測表現 | 策略與"風險池等權持有（日再平衡、不扣成本）"對比累計收益、年化收益、波動、夏普（無風險利率取 0）、最大回撤、Calmar。兩條曲線都從策略首次建倉日起算 |
| 分年度收益 | 逐年與等權基準對比，首尾兩年可能不是完整年度 |
| 參數平原檢驗 | 只改變動量窗口（20 到 200 日，並始終包含當前配置的窗口），在統一區間內對比年化收益、回撤和夏普；會讓統一區間不足 1 年的窗口不列出 |
| 近期調倉記錄 | 最近 10 次調倉的信號日、執行日、調出和調入 |

可回測區間（從首次建倉日到最新收盤）不足 1 年時，年化類指標沒有參考意義，報告只保留數據告警、最新信號和規則說明，並在告警裡說明原因。

建議用 cron 或 CI 在每週最後一個交易日收盤後運行一次。本命令不接入 `--schedule`。

## 配置

以下配置都是可選的，不配置時使用默認值。

| 變量 | 默認值 | 說明 |
| --- | --- | --- |
| `ETF_ROTATION_POOL` | `510300,510500,159915,512890,513100,518880` | 風險池，逗號分隔，會自動去重。默認依次為滬深300、中證500、創業板、紅利低波、納指、黃金 |
| `ETF_ROTATION_SAFE_ASSET` | `511880` | 防守資產（貨幣 ETF）；配置為空表示持有現金 |
| `ETF_ROTATION_LOOKBACK_DAYS` | `60` | 動量窗口（交易日），取值範圍 5 到 500 |
| `ETF_ROTATION_REBALANCE` | `weekly` | `weekly` 或 `monthly`，填寫非法值時回退為 `weekly` |
| `ETF_ROTATION_TOP_N` | `2` | 最多同時持有幾隻，取值範圍 1 到 10 |
| `ETF_ROTATION_SWITCH_BUFFER_PCT` | `2.0` | 換倉緩衝（百分點） |
| `ETF_ROTATION_COST_BPS` | `10` | 單邊交易成本（bp），包含佣金和滑點 |
| `ETF_ROTATION_BACKTEST_YEARS` | `8` | 回測拉取的歷史年數，取值範圍 1 到 30 |

這些配置只在命令行中生效，沒有進入 Web 設置頁。

## 解讀與邊界

- **先看參數平原，再看收益**。如果相鄰窗口之間收益差異很大，說明當前參數的結果主要來自運氣。持有 1 只時路徑依賴最強，所以默認持有 2 只。
- 趨勢輪動的主要價值是**控制回撤**，並不保證跑贏基準。在震盪市裡它會反覆止損；遇到急漲行情（比如跳空的連續漲停）時反應會滯後。回測跑輸等權持有是常見的正常結果。
- **池子要事先定死**。回測時事後挑選"漲得好的 ETF"會產生倖存者偏差。
- **數據源回退可能靜默截斷歷史**。例如東財接口不可用時回退到 Baostock，可能只返回最近一段數據。這種情況會在"數據告警"中列出，此時回測區間會變短，結論要打折扣；不足 1 年時回測部分會直接省略。
- 報告保存或推送失敗只記錄告警日誌，不影響命令退出碼；單隻 ETF 取數失敗或返回格式異常時，會從本次計算中剔除並列入數據告警。
- 回測結果不代表未來收益，不構成投資建議。

## 實現位置

- `src/core/etf_rotation.py`：純邏輯，包括信號、回測、指標和參數掃描，不做任何 I/O
- `src/services/etf_rotation_service.py`：取數、數據告警、報告渲染和推送
- `tests/test_etf_rotation.py`：規則、防未來函數、成本、告警和配置解析的測試
